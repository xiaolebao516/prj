# 多人参考值对照：测量与交付步骤

## 这次更新做了什么

每份新Debug测量日志的第一行自动记录：

- `config.subject.archive_id`：所选档案编号，用于区分同名档案。
- `config.subject.name`：这整次测量开始时的姓名快照。
- `config.measurement_session_id`：整次测量编号。自动续轮、失败后重试属于同一组；重置、完成后重新测或换人进入新组。
- `config.recording_profile=subject-linked-20260918-v1`：本次姓名关联功能标识。

已有算法标识仍为`onset-consistency-20260915-v1`，A0.78、G[-12,0]、首波检查40点等保持原样。本次没有把尚未通过验证的新选点候选装进程序，也没有把参考声速写入算法。

文件名仍是自动生成的`round-时间-随机编号.jsonl`。姓名写在文件内部，所以你不需要给文件重命名；中文、同名、姓名中的特殊符号不会影响文件路径。改档案姓名不会改写旧日志；同一整次测量中改名也仍沿用开始时的快照。

## 第一批怎样测

先找**3人左右，每人3次完整测量**。人少时可以先给2人的数据，不必为了凑人数重复采集。

1. **每人使用一个固定档案。** 姓名可用本人姓名或甲/乙等清晰且不同的简称。选中档案后确认界面姓名正确；不要用同一档案替不同的人测。
2. **提供各自参考值。** 告诉我“档案姓名或简称→参考声速”。有近期同部位参考仪器读数时，保留每次原读数；只有历史样机值时标明“历史参考”，不要把它伪装成当天真值。
3. **设置保持一致。** 先沿用你现有操作：增益1241（滑条最大），A0.78、G[-12,0]。这只是保持当前试测基线，不表示最大增益已被证明最优；本批不同时做增益对比。
4. **每次从独立放置开始。** 在同一侧、同一部位按原操作放置探头，点击“开始检测”。调整到能测后，尽量维持姿态，让程序完成5轮，构成**一次完整结果**。5轮之间会自动继续，不要故意每轮拿开。
5. **一次结束后保存结果，再拿开探头、重新放置，进行下一次。** 每人做3次完整测量。程序会为新的一整次生成新编号，按日志时间能知道先后顺序。
6. **不要只保留接近参考值的结果。** 明显低值、偏高、计数慢和失败的记录也都保留。约60秒仍未完成当前一轮时，可以点“停止检测”，调整后再开始；程序会保留中断日志并把续测归到同组。不要求为了凑数一直等待；卡住的案例同样有用。

若中途确实换了部位/侧别/操作者，或不得不长时间调整，给我一句简短说明，最好附档案名及大概时间。无需标注每帧或手记每个日志文件。

## 发给我什么

1. 新产生的`measurement-experiments`目录里的**全部jsonl日志**，包括中断和失败记录。可以打包整个文件夹；旧日志仍保留旧格式，我会按功能标识区分，不会给旧数据猜姓名。
2. 一份很短的参考说明，例如：

```text
甲：参考3820 m/s，9月19日同部位参考仪器测得；原读数3815、3825。
乙：参考3900 m/s，以前样机大致值，日期不确定。
丙：参考3850 m/s，来源/日期……
均由同一人操作，同侧同部位，每人3次，整次之间拿开重放。
特殊情况：乙第2次中途重新找了位置。
```

不需要发`patients.xml`或其他档案库。实验jsonl已包含你授权记录的姓名和档案编号。

## 这批数据将怎样使用

按档案编号/姓名分人，再按整次测量编号分组，比较同一人的多次结果与其个人参考值；同时看完成用时、中断、有效帧及原始波形。不同人的结果不混成一个平均值，也不统一向3850校正。

日志仍不能自动判断具体哪一帧发生了拿开重放；上面的“整次之间重放”流程提供操作边界，中途额外重放需简短说明。软件关联已测试，实际采集和参考准确性仍需这次人工测量来验证。
