# 门控诊断观察指南

> **受众：** 受监督的研发与实验室操作者。
> **职责：** 帮助查看输出、记录条件并执行可逆排查；不定义代码常量、参数修改、算法验收、医学判断、校准有效性或计量结论。工程语义见 [Agent 调试参考](../../.agent/reference/operations/debugging.md)。

## 开始前

- 使用项目规定的 Qt 工具链构建，并在 Qt Creator 的“应用程序输出”中观察程序输出。
- 记录构建版本、设备与探头标识、测试介质、温度来源、耦合方式和操作者动作。
- 不在截图或日志中保留患者身份、账号密码、设备隐私数据。
- 人体或硬件操作必须遵守已批准的实验室方案；故意错位等探索动作不得用于正常患者操作。

## 观察输出

程序可能在采集过程中和轮次结束时输出多行统计，包括闸门拒绝计数、`CorrA` 分布以及稳定性类别（当前标签包括 `StabWarm`、`StabConc`、`StabLock`）。请保留完整的一组输出和对应总帧数，不要只截取最高百分比。

D/G 竖条与橙色提示是软件定位线索。可按界面提示轻微调整角度或左右位置，但它们不能单独证明姿态正确、骨骼状态、硬件故障或临床结论。

## 可逆排查

1. 检查探头接触、耦合剂覆盖、气泡、连接和操作者手部稳定性。
2. 只做可恢复的小幅位置/压力调整，并记录调整前后条件。
3. 如果输出持续异常、设备断连、患者不适或无法保持受控条件，立即停止采集。
4. 保存最小可复现日志并交由工程人员结合当前代码分析。

拒绝统计可帮助选择调查方向，但各计数可能重叠，最高百分比不能直接等同于根因。不得因统计偏高自行放宽门限或改参数。

## 证据边界

- 软件实际运行、代码路径检查和实验室硬件验证必须分别标注。
- 普通铜块、塑料块或单次人体观察属于探索性证据，不等同于 REQ-009 的合格试块校准。
- 未实际验证的温度、耦合、设备精度、患者影响或医学结论必须明确标记为未验证。
