# B路轮间差异调查：局部搜索截断与波形歧义

## 结论与决定

19份已有记录共5423帧，原始B路重建4802个有效PairResult，另外621帧的无效状态也与日志一致。第二组前两轮的局部相关峰被搜索上限截断，原患者流程仍可将这些估计计入有效值。原先“波形已经匹配，所以只剩姿态门槛”的理解不成立。

但截断不是全部问题：固定原30个保留帧去掉平台偏置、换短/长窗口，都不能消除第二组约300m/s的轮间差异；扩大搜索甚至加重差异。因此不部署新的B估计器，不把G简单放宽，不指定3900为正确簇。当前没有证据支持一个能同时显著减轻找位置、保持小误差的参数包。

## 1. 搜索上限能决定估计值

现代码 `SignalProcessor::refineLagByPositiveCrossCorrelation` 先由包络起点差得到roughLag，再在roughLag附近搜索。roughLag位于物理区间时，局部半宽最少30点；所选相关峰可能正好位于局部搜索末端。后续“高相关平台”再按速度相关的经验比例选点。

第二组第1、2轮各自最终保留的30帧，原窗口最大相关点全部落在局部搜索上限。当前患者流程 `notBoundary = (bRes.refinedLag < 260)` 只限制一个大的lag上界，不检查这个局部搜索区间。`B_jump <= 70` 也不等价于检查局部峰完整性。因此局部截断不会被这些现有检查阻止。

具体例子：第二组第1轮 `round-20260907-020810-166-5135abd5-2994-46e2-a660-6c18d6ec85d9.jsonl` 序号183，roughLag105，搜索92..135，最大相关在135处0.7690，平台选134，SOS3656.72。向两侧最多补搜15点时，在140找到0.8563的完整局部峰，对应3500。这说明原搜索截断了该相关峰；不证明140就是物理上正确的传播时间差。

## 2. 固定波形，只改粗定位提示也会变

诊断保持原始滤波波形、早端相关窗口不变，只把传入相关函数的roughLag提示分别减5、加5，调用未修改的实际函数。不是模拟探头移动，也不是重新检测整条算法。

第一组150个保留帧两种提示下最终lag都不变。第二组第1至5轮，两种提示下保持原lag的帧数依次为0、0、0、21、4（每轮30）。

第二组第2轮序号31：原roughLag101、最终lag130、SOS3769.23。提示减5时选lag126（SOS3888.89，相关0.6660），提示加5时选lag131（SOS3740.46，相关0.8046）。两者都超过B相关底线0.55，说明单靠相关底线不能消除这种敏感性。其他A/D/G和稳定性没有重算，所以不能将其说成两种都会完成测量。

第二组第1轮负向扰动后的相关性全部低于0.55；摘要中该扰动的数值只能解释函数敏感性，不能当作可接受测量值。

## 4. 修改方向与证据边界

确定值得处理的代码问题是：区分完整的局部峰和被边界截断的相关曲线，并避免粗定位边界直接支配可信读数。但目前有三个不能省略的限制：

1. 单纯拒绝边界峰可能增加无法推进的时间；不是本项目“更容易测”的解决方案。
2. 单纯补搜或选最高相关峰，会改变SOS并可能选择其他波段；不能直接部署。
3. 即便消除平台偏置，第二组仍有明显不同的稳定波形估计。没有同期样机参考，无法确认应保留哪类信号，也不能把所有低值自动认定为错误。

后续算法候选应把首波识别、局部峰完整性和跨窗口的一致性一起评估；必须重新计算依赖B的A定位/D/G及完整测量流程。现有研究尚未得到满足上述条件且能改善定位的可部署候选。

现在补测的目的不再是让用户找“为什么卡住”，而是提供缺失的参考标签。最小第一步：用户本人在同一时段、同一侧同一测量部位用样机测2–3个读数，再用当前双段试测版正常完成一组五轮，保留独立重新放置后的结果和全部自动日志；若卡住则保留失败日志，不要求手工记录每一帧的原因或计时。先不要求找其他同学。这只是第一组配对探索证据，不能单独完成准确性/跨人群验收。
