# 9 月验收前软件明显问题审计

日期：2026-07-22

范围：独立仪器上位机的数据可靠性、显著性能、UI 与操作流程

性质：只读审计；本轮未修改产品代码、算法、参数、数据格式或依赖

## 结论

当前软件已具备可演示的登录、档案、检测、历史、报表、校准和换机备份流程，但尚不宜直接宣称满足 9 月医院侧验收。最需要先处理的不是复杂安全设计，而是以下两类问题：

1. 面向使用者显示的 T/Z 值、骨强度、相对骨折风险和相对骨龄仍包含代码中明确标注为“临时”的参考曲线和估算公式，缺少正式依据。
2. 档案 XML 加载失败后程序仍保持可编辑状态，后续保存可能用空列表覆盖原文件，存在严重的数据损失风险。

本轮共保留 2 项 P0、4 项 P1、5 项 P2。未发现需要立即引入数据库、云服务、DICOM/HIS、复杂权限系统或全面加密的证据。

## 分级定义

- P0：会阻断正式验收，或可能造成严重数据破坏/错误结果，必须先决策或修复。
- P1：高影响可靠性问题，应在 9 月前修复并验证。
- P2：明显但影响较低或需要较长运行时间才出现，建议随本轮整理修复。
- P3：已知限制或普通优化，本轮不建议投入。

## P0

### P0-1 派生结果参考库和解释边界待算法负责人确认

- 证据：`src/bonehealth.cpp:31-32` 明确说明年龄参考曲线只是临时曲线；`src/bonehealth.cpp:87-88` 明确说明骨折风险为临时估计。
- 调用：`src/mainwindow.cpp:1144-1159` 使用固定年轻人均值、固定标准差和上述临时函数计算 T/Z 值、骨强度、骨折风险和骨龄；随后在 `src/mainwindow.cpp:1165-1185` 显示并写入正式历史记录。
- 影响：软件界面和报表会把缺少正式依据的估计值呈现为患者结果。这不是普通 UI 问题，而是正式验收边界。
- 后续轻量核对：T/Z 的标准化代数形式没有明显错误；`1.5^(-T)` 的每标准差风险倍率数量级也未见明显异常。但公开指导要求 QUS 使用设备、部位和目标人群适用的参考数据库与独立验证阈值，仓库中的 `4150 / 4137 / 115.2`、年龄曲线和固定男性偏移无法由公开资料确认。当前年龄曲线与年轻人均值还存在内部不自洽，因此不能据此认定参考数据正确。来源：[FDA 骨超声指导](https://www.fda.gov/medical-devices/guidance-documents-medical-devices-and-radiation-emitting-products/bone-sonometers-class-ii-special-controls-guidance-industry-and-fda-staff)、[ISCD 2023 官方立场](https://iscd.org/official-positions-2023/)、[中国大陆桡骨 SOS 参考研究](https://pubmed.ncbi.nlm.nih.gov/24951371/)。
- 状态：公式框架未发现需要本轮紧急改动的明显错误；参考常量、年龄曲线和结果解释仍需师兄/课题组确认。本轮不修改算法代码。
- 最小处理建议：在老师/医院确认依据前，二选一：提供经批准的参考数据库与判定公式；或暂时隐藏/明确标注这些派生结论，只保留实际测得的 SOS。任何算法或判定修改都需单独批准。

### P0-2 档案加载失败后仍可继续写入，可能覆盖原数据

- 证据：`src/patientstore.cpp:94-116` 和 `src/patientstore.cpp:136-149` 在 XML 损坏时返回失败；`src/mainwindow.cpp:3907-3912` 只弹出警告，没有禁止新增、编辑、删除或结果保存。
- 触发：`patients.xml` 或 `measurements.xml` 损坏/不可读，启动时列表保持为空；用户忽略警告后新建档案或完成保存。
- 影响：后续 `QSaveFile` 会原子地写入新的空/部分列表，但这也会把原有可恢复文件整体替换，造成二次数据破坏。
- 状态：代码路径已证实；为避免触碰真实档案，本轮未做破坏性复现。
- 最小修复建议：加载失败后进入“档案只读/不可检测”保护状态；自动保留异常文件副本；只有恢复成功或用户明确新建空数据库后才重新允许写入，并增加患者/测量 XML 损坏测试。

## P1

### P1-1 串口帧通道号未校验，异常帧可越界写内存

- 证据：`src/mainwindow.cpp:1457-1509` 校验了长度和帧尾，但没有校验 `ch` 是否为 1 至 4，随后直接访问 `g.ch[ch - 1]` 和 `g.has[ch - 1]`。
- 影响：噪声、错帧或下位机异常给出 `ch=0` 或 `ch>4` 时会发生越界写，可能闪退或破坏内存状态。
- 最小修复建议：在解析 payload 前拒绝并丢弃通道号不在 1..4 的帧，补充无效通道边界测试。

### P1-2 缺少通道的帧组会持续保留，通信异常时内存可显著增长

- 证据：`src/mainwindow.cpp:1507-1529` 仅在四个通道全部到齐后删除 `frameGroups[idx]`；没有超时、容量上限或按帧序号淘汰。
- 触发：串口仍保持连接，但某一通道长期缺失或持续产生不完整帧组。
- 影响：每组最多保留多路、每路最多 5000 个采样；持续运行可造成明显内存增长和界面迟滞，严重时退出。
- 最小修复建议：限制未完成组数量，并按最新帧号/时间淘汰旧组；串口状态异常时立即清空。

### P1-3 删除患者时两个 XML 不能形成一个原子事务

- 证据：`src/mainwindow.cpp:3956-3967` 先保存删除后的 `measurements.xml`，再保存 `patients.xml`；第二步失败时只做尽力回滚。
- 触发：删除患者后，两个文件提交之间断电/进程终止，或第二个文件写入与回滚都失败。
- 影响：患者仍存在，但其历史已经被删除。
- 最小修复建议：不改变 XML 格式的前提下，删除时先保存患者文件再保存测量文件，使中断最多留下可清理的孤立历史，而不是丢历史；同时保留操作前双文件备份并在启动时检测未完成事务。

### P1-4 保存失败后的检测结果只在内存中，关闭程序没有保护

- 证据：`src/mainwindow.cpp:1186-1194` 保存失败时保留 `pendingMeasurement` 并提供重试；主窗口没有 `closeEvent`，关闭前不会提示尚有未保存结果。
- 触发：磁盘只读、空间不足或写入失败后，操作者直接关闭程序。
- 影响：刚完成的五轮结果永久丢失。
- 最小修复建议：主窗口关闭时检查 `hasPendingMeasurement`，明确提示重试保存或确认放弃；必要时把待保存结果写入独立恢复文件。

## P2

### P2-1 未连接串口也能进入“停止自动采集”状态

- 代码证据：`src/mainwindow.cpp:550-582` 启动自动定时器前不检查串口；`src/mainwindow.cpp:585-586` 的发送函数随后静默返回。
- 实际走查：未连接设备点击“自动采集”后，按钮立即变为“停止自动采集”，没有错误提示，也不会产生数据。
- 建议：与“获取波形/开始检测”保持一致，未连接时直接提示“请先连接串口设备”，不要切换运行状态。

### P2-2 档案页操作区分组混乱且选择规则不一致

- 实际走查：正常档案模式为上排 4 个按钮、下排 2 个按钮；搜索、添加、历史和删除混在同一网格中，正是用户指出的明显不协调布局。
- 代码证据：`ui/mainwindow.ui:1933-2022`；查看历史使用当前行并可回退到勾选项，而删除只接受复选框，见 `src/mainwindow.cpp:4136-4195` 与 `src/mainwindow.cpp:4314-4329`。
- 建议：左侧保留搜索条件与单个“查找”，右侧单独排列“添加、查看历史、删除勾选项”；把删除按钮改名为“删除勾选项”，明确单选与多选规则。

### P2-3 主界面存在占位标题和无功能按钮

- 实际走查：主界面可见多个英文占位标题“GroupBox”；“WIFI”按钮可点击但没有任何反馈。
- 代码证据：`ui/mainwindow.ui:156-176` 定义 WIFI 按钮，但 `src/` 与 `include/` 没有连接或槽函数；`ui/mainwindow.ui:302-363` 和 `ui/mainwindow.ui:1100-1102` 共保留四个 `GroupBox` 标题。
- 建议：若当前版本不支持 WIFI，直接隐藏/删除该按钮；把占位标题替换为“波形、声速趋势、检测过程、测量部位”等正式中文或取消标题框。

### P2-4 新建档案布局松散且字段缺少基本约束

- 实际走查：1080p 最大化时，基本资料和身高/体重之间出现大块空白，保存/返回按钮远离表单主体。
- 代码证据：`src/mainwindow.cpp:4438-4456` 只校验姓名和 ID；身高、体重没有数值范围验证，出生日期也未限制为今天及以前。
- 影响：容易录入任意字符串或未来出生日期；年龄会被折算为 0，进而影响派生结果。
- 建议：使用紧凑表单布局；增加身高/体重数值校验、出生日期上限和清晰的单位/错误提示。

### P2-5 调试自动采集的趋势序列会无限保留历史点

- 证据：`src/mainwindow.cpp:2097-2118` 每帧追加一个点，只移动 X 轴显示最近 50 点，没有删除旧点；调试自动采集也没有时长上限。
- 触发：长时间保持自动采集。
- 影响：点数持续增长，可能逐渐增加绘图和内存开销。
- 建议：序列只保留最近 50 至 200 个点，或为调试自动采集设置明确的停止/清空策略。

## 已验证的正向结论

- 账号、患者、检测记录和校准保存均使用 `QSaveFile`，单个文件写入具备原子替换能力。
- 账号与校准文件已有损坏备份/恢复路径；问题主要集中在患者与检测历史的失败保护。
- `angle_features.csv` 的逐帧输出受 `kDebugPerFrame=false` 保护，本轮不把它列为正式性能问题。
- `tests/portable_handoff_tests.ps1` 已实际通过：覆盖完整换机包、数据哈希、重复备份不覆盖、无患者历史场景和缺少运行库时拒绝生成。换机工具目前不是阻塞项。
- 当前档案数量下未观察到明显卡顿，因此没有把普通 XML 全量重写或 O(P×M) 列表扫描列为近期优化任务。

## 已知限制（P3，本轮不建议扩展）

- 默认管理员口令简单、盐化 SHA-256 不是慢速密码派生函数、本地 XML 未加密。
- 这些属于独立实验室上位机的已知部署限制；除非老师或医院提出明确要求，本轮不引入服务器、复杂权限、审计日志或全面加密。

## 外部验收边界

本轮没有真实完成以下测试，因此不得据此宣称通过：

- 真实设备五轮检测、自动保存和同患者再次检测；
- USB 热拔插、驱动异常和重连；
- 合格试块、外部温度计、真实探头下的校准精度和重复性；
- 实体打印机 A4 输出；
- 医院侧未提供的正式验收条款。

## 建议修复批次

1. **验收阻塞决策**：先由老师或算法负责人确认参考数据库与结果解释边界；若无法在验收前确认，再决定隐藏或降级显示派生结论。
2. **数据与串口可靠性**：加载失败只读保护、患者/历史删除一致性、未保存结果关闭保护、通道号校验和不完整帧淘汰。
3. **明显交互整理**：档案页重新分组、未连接自动采集提示、移除 WIFI 空按钮和 GroupBox 占位标题、压缩建档表单并补基本校验。
4. **验证**：新增患者存储损坏/回滚测试和串口解析边界测试，再执行完整 Debug 构建；真实设备、USB、打印和校准仍由实验室现场验收。
