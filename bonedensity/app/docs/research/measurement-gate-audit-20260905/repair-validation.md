# 2026-09-05：状态修复与自动试测记录

## 这一版做了什么

- 原来信号连续不合格，之前的稳定窗口仍可能一直留着。现在连续 10 帧不通过初筛时，清掉旧窗口和当前轮的旧样本；少于 10 帧的短暂中断保留进度。这里复用了原来的失锁计数，没有改 D/G、相关性、SOS 等数值阈值。
- 原来换到明显不同的声速簇，可能把前后两个位置的值混在一轮里平均。现在原有稳定锁丢失时，七组当前轮数据和进度一起清空，继续自动采集。已完成的轮次不删除。
- 无法计算当前姿态时，D/G 数字显示 `--`，原进度条置为不可用；取得可计算的特征后恢复。没有移动进度条、改中线或改映射，也没有恢复快速变化的指导句。
- Debug 试测程序每次开始一轮时自动新建记录，保留四通道原始波形、实际特征点及 A 特征分支、判定结果、时间和清空/结束事件。不写入姓名、患者编号、账号或档案资料，不上传记录。

这不是“放宽后更容易测”的验证结果。持续无效时重新累计可能增加部分场景耗时，目的是避免用旧证据或混合位置凑满一轮。是否应采用其他保留/恢复策略，需要试测记录比较。程序没有修改声速公式、相关峰选取、D/G 定义、数值阈值或 80 ms 采集设置。

## 你怎么试

1. 关闭旧程序，打开本项目 `build/debug/debug/BoneDensity.exe`，先只测自己。
2. 在原定的桡骨测量部位，像平时一样涂耦合剂、调整探头、完成五轮。测不出来也保留这次记录，不需要判断原因、计时或一直硬等。
3. 可以重复几次，观察是否依旧需要很精细地找位置、有没有卡住、结果是否明显变散。提供同一时期样机测自己的 SOS 读数作为比较；这只是参考，不等于计量真值。
4. 测完停止采集或关闭程序，把该程序旁边的 `measurement-experiments` 文件夹交给开发分析即可。无需运行脚本；不要发 `patients.xml` 等档案文件。若底部提示实验记录未保存完整，请一并告知。

本阶段只用于研发自测，不证明患者测量准确性，也不支持将此人的结果范围当成所有人的目标范围。先看自己的数据，再决定调参候选与他人测试。

## 记录边界

- 每轮为唯一命名 `round-*.jsonl` 文件，复制程序文件夹后路径仍相对于程序；普通 Release 不自动开启记录。
- 单文件最多 256 MiB；本目录已有记录计入 2 GiB 总预算。达到限制时停止记录并提示，不自动删除旧记录，不改变测量是否有效的判定。这是单实例本地预算，并非并发进程共享的硬磁盘配额。
- 文件采用缓冲写入，一轮结束/停止/断连时刷新并关闭；异常断电可能使末尾记录不完整。正常文件有结束事件；截断文件不能当成完整测量。
- 时间为单轮内单调时钟；`processing_ms` 仅覆盖特征检测及门控，不包含此前滤波、之后绘图、串口等待或本帧日志编码/写入。不能把它当成整轮耗时。
- 记录针对成功组装并进入处理的四通道帧，**不包含串口残缺包**。完全没有收到帧的空白、暂停提示期间，会表现为时间间隔或暂停事件；不能据此自动认定具体硬件故障或姿态原因。
- 每帧可包含多个失败条件；`stability_evaluated=false` 表示前置条件没通过，不能把 `stable=false` 单独解释为稳定性门槛过高。
- 原始波形有明确编码（16 位无符号、小端、Base64，通道 BC/BD/AC/AD），实际 A/B 特征另行记录。参数快照包括当前探头基线、采样周期、门控参数、增益和编译标识；其他固定处理步骤须配合同版源码解释。
- 记录虽不带姓名和编号，仍是人体测量数据，不应公开发布；已加入 Git 忽略，避免误提交。
